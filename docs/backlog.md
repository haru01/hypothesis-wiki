# 改善バックログ

このリポジトリ（スキーマ層・ツール・スキル）の改善余地のうち、**いま実害が出ているもの**を載せる。
実害が無いものは「保留」に一行で退避し、見送った判断は「方針確定・不採用」に理由だけ残す。

対応済み項目は本文に残さない。経緯は git 履歴で辿る（[README.md](README.md) の「消えた記録の辿り方」）。

ID 接頭辞は改善の軸を表す: **OI**＝オントロジー ／ **SI**＝スキル ／ **KG**＝ナレッジグラフ ／
**AR**＝アーキテクチャ。番号は軸ごとに既存最大+1で採番し、**再利用しない**
（過去の番号は欠番のまま。学びレコードやコード docstring からの既存参照が意味を保つため）。

## P1. 実害あり（いま直す）

### AR-12: `fictional_activities` の本文マーカー語フォールバックが実データの実験を誤分類する

- **対象**: `tools/records.py`（`fictional_activities`）・`tools/hwlint.py`（`check_fictional_cap`）・
  `tools/gen_views.py`（`header_lines`）
- **状態**: 未対応（回避のみ。2026-07-31 `SELF-TEST-006` 立案時に検出）
- **課題**: 判定は「出典冒頭の宣言（一次情報）」＋「本文マーカー語（後方互換のフォールバック）」の2経路だが、
  後者は**レコードが何のデータで作られたか**ではなく**何について書いてあるか**を拾う。
  実データの実験計画（`SELF-TEST-006`）が「過去ラウンドの根拠が架空だった」と経緯を説明しただけで
  架空活動リストに載り、全ビューのヘッダーが「これら由来の確信度・判断は実データ未検証」と**逆の事実**を表示した。
  `check_fictional_cap` は確信度履歴が引く活動を見るので、実データの学び(LEARN)が同じ理由で誤分類されると
  **実観測の確信度に上限8の蓋がかかる**（9-10 が永久に取れない）。
  是正・監査系のレコード（`/chabudai`・出典突き合わせ）は本質的に架空データについて語るので、構造的に踏みやすい。
- **改善案**:
  - (a) TEST/LEARN の frontmatter に明示フィールド（例 `data: real | simulated`）を置き、判定の正本にする。
    語の有無に頼らないので、経緯の説明と自身のデータ種別が混ざらない。**第一候補**。
  - (b) フォールバックを「出典を持たないレコードのみ」に限定する（出典があるならその冒頭宣言だけを見る）。
    現在は出典があっても本文マーカー語が先に効く（`records.py:139` の early `continue`）。
  - (c) 少なくとも、マーカー語の判定を**引用ブロック・コード内を除いた本文**に絞る。
- **回避（暫定）**: `SELF-TEST-006` は本文でマーカー語を使わず「実観測でない生成データ」と言い換え、
  先行ラウンドはレコードIDで参照した。同カードにその規律を注記済み（LEARN・生データにも及ぶ）。
- **根拠**: `records.py:124-146`（2経路の判定と early `continue`）・`hwlint.py:422-441`（履歴行の活動を見る蓋）・
  `gen_views.py:147-156`（全ビューのヘッダー警告）。

## 方針確定・不採用（再検討の契機つき）

「検討済みで見送った／こう決めた」を残す節。**知らずに直しにかかるのを防ぐのが目的**なので、
理由は残し、詳細な論拠は git 履歴に委ねる。

- **レガシーな `evidence-tag` warning は retro-fix しない**（旧 KG-10）— 証拠種別タグは確信度履歴の
  過去行に書くものだが、履歴は追記専用（不変ルール2）なので過去行にタグを足すこと自体が規約違反。
  **構造的に解消不能**。したがって **warning 0 を目指さない。error 0 を不変条件とし、warning は
  真の未達を映す計器として読む**。解消したいなら新しい検証を回して階梯タグつきの行を追記するか、
  `/chabudai` で確信度を引き下げる。
- **`sources/` に残る、移行で削除された回顧型 ACT 宛の wikilink は修復しない** — 不変層を
  書き換えないこと（不変ルール3）を優先した決定。実害は Obsidian 上のリンク切れのみで、
  `/lint` もサイトビルドも対象にしていない。
- **ベクトル検索／ハイブリッド検索・確信度付き BFS 探索ツール・デスクトップGUI・
  コミュニティ検出（Louvain 等）は採らない**（旧 OI-H）— 1案件が十数〜数十レコードの規模では、
  Claude が `wiki/` を直接読む現方式より精度・保守性ともに劣化する。導入コスト過大。
  可視化は Obsidian ＋ `relations` ビューのグラフ診断で足りる。
- **抽出量キャップ（Extraction cap）は該当なし**（旧 KG-09）— 取り込みが人手ペースで、
  暴走コストの経路が無い。`sources/` へのバッチ投入経路を作るなら再検討する。
- **`--no-verify` によるフック迂回は許容する** — 技術的に塞げないし、フックは強制装置ではなく
  規律の道具として置いている。
