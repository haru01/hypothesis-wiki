[[SELF-TEST-006]] のテストカードの**方法**を現場の会話に落としたスクリプト。1インタビュー 45〜60分。
`〈…〉` は対象者に合わせて置き換える。土台は [templates/problem-interview-script.md](../../../../templates/problem-interview-script.md)、心得の正典は [playbooks/interviewing.md](../../../../playbooks/interviewing.md)、ステージの問いは [playbooks/cpf.md](../../../../playbooks/cpf.md)。

対象仮説: 状況・行動 [[SELF-H-001]] [[SELF-H-002]] [[SELF-H-003]] ／ 課題 [[SELF-H-004]] [[SELF-H-006]] [[SELF-H-008]]

## 使う前に（CPF の鉄則）

- **過去の事実を聞く。未来の意向・仮定は聞かない。**「〜だったら使いますか？」ではなく「直近で〜したのはいつ、何をしましたか？」。
- **ソリューションもこちらの仮説も語らない・示唆しない。** 「困りましたよね？」は禁句。
- **反証を能動的に探す**（反証枠）: 各テーマで支持例を聞いたら、**必ず対で「逆に、うまくできた／問題が起きなかった例は？」**を聞く。確証バイアスの自己防衛。
- **切実さは実コストで測る**: 「大変だった」ではなく「**何に・どれだけ**（時間／金／手戻り／信頼）を実際に払ったか」。数字が出なければ × と記録する。
- **沈黙を待つ。** 一般論が出たら「直近の具体例は？」「そのとき実際どうしましたか？」で事実に降ろす。
- **発見枠は伏せて聞く**（後述5章）: 既存仮説を相手に語らず、**自発言及だけ**を listen-for として拾う。

## 記入ヘッダー（インタビューごとに埋める）

- **対象者ラベル**: `対象者U` から連番で一意に振る（`対象者U` `対象者V` `対象者W` `対象者X` `対象者Y` `対象者Z`、7人目以降は `対象者AA` `対象者AB` …）。**A〜T は既存3ラウンドで消費済みなので使わない。文字を飛ばさず、人数と命名数を一致させる**（[[SELF-LEARN-006]] 名寄せ規約）。
- **セグメント**: `説明相手を持つ層`（この正規名で書く。言い換えない）
- **現行ツール（1章で確定・必須）**: 学びの記録に使っているツール名をすべて（`Miro` `Notion` `Slack` `スプレッドシート` … 個別に書く。併記は `Miro/Notion` の形）
- 実施日 / 所要時間 / 記録係 / 録音可否:
- 説明相手（上司・投資家・メンター・チームの誰か）:

## 0. 導入・ラポール（3分）

> 本日はお時間ありがとうございます。新規事業やプロダクトの**検証を普段どう進めているか、その事実**をうかがいたいです。良し悪しを評価する場ではなく、実際の様子を教えてください。こちらから何かを提案する場ではありません。答えづらいことは飛ばして構いません。（録音可否の確認）

## 1. スクリーニング＋現行ツールの確定（7分）

想定した状況・顧客に本当に当てはまるかを事実で確かめ、**この後の話がどのツール環境の話なのかを先に固定する**（[[SELF-LEARN-006]] ①の再発防止）。

- 直近3ヶ月で、顧客インタビューや小さな実験で仮説を確かめたことはありますか？ 最後にやったのはいつですか？
- そのときの役割・チーム規模・扱っていたテーマは？
- 検証の進捗を**定期的に説明する相手**はいますか？（上司・審査会・投資家・メンター・チーム）どのくらいの頻度で？
- **いま検証の学びを書き留めている場所を、全部挙げてください。**（ツール名を列挙してもらう。個数も数える）

> 「直近3ヶ月の検証」または「説明する相手」が無ければ、無理に続けず**対象外として記録する**（サンプルの質を守る。対象外も人数に数えず、ラベルは消費しない）。

## 2. 直近エピソードの再現（15分）— 状況・行動仮説の検証

> 直近で検証を1つ、**最初から最後まで**順番に教えてください。

- 誰に・何を・どうやって確かめましたか？
- それは**作り込む前**でしたか、**作った後**でしたか？（[[SELF-H-001]] 支持側）
- 同じような検証は直近3ヶ月で**何回**やりましたか？（反復の事実。回数を数字で）
- **逆に**、検証を一度もせずに作り始めた／一度きりで終えた案件はありますか？ そのときはなぜ？（＝[[SELF-H-001]] 反証側）
- 得られた学びを、**そのときどこに・どう残しました**か？（1章で挙がったツールのどれか。複数なら全部）
- その学びを**後から探し直した**ことはありますか？ どこを見て、どれくらいかかりましたか？（[[SELF-H-002]] 支持側・実コスト）
- **逆に**、学びが1箇所にまとまっていて探すのに苦労しなかったケースはありますか？ どうまとめていましたか？（＝[[SELF-H-002]] 反証側）
- 元々の見立て（仮説）や確信の度合いを更新しましたか？ **学びを得たのはいつで、更新したのはいつですか？**（[[SELF-H-003]]・**2つの日付を必ず取る**）
- 更新しなかった／後回しにした場合、それは何のタイミングでまとめましたか？（報告前・レビュー前など）
- **逆に**、学んだその日に更新した例はありますか？ 何がそれを促しましたか？（＝[[SELF-H-003]] 反証側）

## 3. 課題ごとの深掘り＋実コスト（20分）— 課題仮説の検証

3件それぞれについて「支持側 → 反証側 → 実コスト → 代替手段」を1セットで聞く。**「困りましたか？」と聞かず、実際の場面を語らせる。**

### 3-1. [[SELF-H-004]] 意思決定の経緯が後から辿れない

- 過去の判断について「**なぜそう決めたのか**」を後から思い出せず／説明できず困った場面はありますか？ 何が起きましたか？（支持側）
- そのとき**何に・どれだけ**（時間・やり直し・信頼）かかりましたか？（実コスト。数字で）
- **逆に**、過去の判断の根拠をすぐ再構成できたケースはありますか？ 何が残っていたからできましたか？（＝反証側）
- いまはどうやって凌いでいますか？（代替手段）その代替手段自体の手間は？
- 担当交代や引き継ぎで、経緯が失われた／失われなかった例は？

### 3-2. [[SELF-H-006]] 好意的反応を購買意向と取り違える

- 顧客の反応が**良かった案件**で、その後の実際の購入・継続はどうなりましたか？ 体感と実績のズレはありましたか？（支持側）
- ズレていた場合、その先行実装・準備に**どれだけ**（工数・期間・費用）かけましたか？（実コスト）
- **逆に**、好感触と実際の購買意向を**取り違えずに見極められた**ケースはありますか？ **どうやって**見極めましたか（仕組み・基準がありましたか）？（＝反証側）
- 「いいですね」と言われた案件と実際に契約に至った案件の**比率**を出せますか？

### 3-3. [[SELF-H-008]] 検証の根拠を説明できず合意形成が停滞する

- 報告・レビューの場で、**証拠の受け取り方が割れて**結論が持ち越された場面はありますか？ 何が起きましたか？（支持側）
- その報告の準備と、持ち越しによる遅れに**どれだけ**（日数・工数）かかりましたか？（実コスト）
- **逆に**、証拠の見方が揃って滞りなく決まったケースはありますか？ そのとき何が共通の土台になっていましたか？（＝反証側）
- いまはどうやって凌いでいますか？（資料の作り込み・事前の根回し等）その手間は？

## 4. 代替手段と支払い実績（5分）— 切実さの代理指標

- この種の困りごとのために、**これまでに実際にお金や工数を払った**ことはありますか？（有料ツール導入・外注・専任の工数・自作の仕組み）**何に・いくら／何時間**でしたか？
- 満足していますか？ 足りない点は？
- 逆に「わざわざ対処していない・放置している」ものはどれですか？（＝切実でないシグナル）

> **過去の支払い実績のみ**。「払いますか？」の未来意向は聞かない・成功基準に数えない。

## 5. 発見枠（7分）— 既存仮説を伏せた白紙の探索

**こちらの仮説・製品案を一切出さない。**オープンに聞き、**相手が自発的に言ったことだけ**を原文で記録する。

- 今日話した以外で、検証の進め方について**一番もやもやしている**ことは何ですか？
- その学びの記録は、**誰が書いて、誰が見ますか**？（事実として聞く。人数・役割）
- 直近3ヶ月で、検証の進め方を**自分たちで変えた**ことはありますか？ 何を、なぜ変えましたか？
- 逆に「変えたいのに変えられていない」ことは？ 何が邪魔していますか？

**インタビュアー用 listen-for（相手には言わない・自発言及のみ○）**

- (a) 記録・検証が**個人単位か共同編集か**、共同での書き込み・レビューへの言及（[[SELF-LEARN-004]] で出た「共同編集派」シグナルは既存の状況・行動仮説がどれも捕らえていない）
- (b) 既存8仮説のどれにも当てはまらない不満・回避行動
- (c) 想定と違った発言（驚き）

> **発見枠で出たシグナルは既存仮説の確信度を動かさない**（テストカードの成功基準どおり）。学び（LEARN）の「驚き・想定外」に置き、`/formulating` の新規仮説候補として渡す。

## 6. クロージング（3分）

- 今日の話で、**一番やっかいだった**のはどれですか？（本人の優先順位を最後に確認）
- 同じような状況の方を紹介いただけますか？（次の対象者の獲得）
- 後から思い出したことがあれば後日でも歓迎です。

| 仮説 | これが観測されたら**反証側** | これが実コスト／行動付きで出たら**支持側** |
|---|---|---|
| [[SELF-H-001]] | 作る前の検証をしていない、または一度きりで反復していない | 作る前の検証を反復した〈行動〉（回数つき） |
| [[SELF-H-002]] | 学びが1箇所に構造化して集約され、探索・再構成にコストが生じていない | 記録先が3ツール以上に分散し、探し直しに時間を払った〈実コスト〉 |
| [[SELF-H-003]] | 学習した直後に仮説・確信度を更新している | 学びを得た日と更新した日が**同日でない**〈行動〉（2つの日付） |
| [[SELF-H-004]] | 過去の判断根拠を容易に再構成でき、散逸に実コストを払っていない | 経緯を再構成できず払った時間・やり直し・信頼の〈実コスト〉 |

| [[SELF-H-008]] | 報告の場に証拠の共通の土台があり、解釈が割れず滞りなく決まる | 持ち越しによる遅れ・説明準備の〈実コスト〉 |

**判定の線**（人数の床＝5名未満なら発火しない）: 課題3件は〈自認〉かつ〈実コスト〉が **60%以上**で支持。行動 H-001/H-002 は **80%以上**、H-003 は **60%以上**（80%以上なら確信度7）。**〈発言〉だけは支持に数えない。**

## 禁止・注意

- **ソリューションもこちらの仮説も語らない・示唆しない。** 相手から「こういうのが欲しい」と出ても事実として記録するに留め、こちらから膨らませない。
- 誘導質問（「〜で困りますよね？」）・二択の押し付けをしない。
- **未来／仮定（「もし〜なら」「無料なら試す」「あったら使う」）を成功基準の根拠にしない。** 「無料枠で始める」は〈支払い〉ではない（[[SELF-LEARN-006]] ②）。
- 支持例だけを集めない。**各テーマで必ず反証側（逆の例）を1問聞く。**
- **事前登録した反証条件＝テストカードの成功基準は変えない**（後知恵バイアス防止）。
- **架空・シミュレーションの回答を混ぜない**（混ぜると [[SELF-LEARN-005]] が裁定したカテゴリーエラーが再発する）。

## 記録のコツ（`/learning` に効く）

- **事実（発言・行動）は原文で引用**し、**解釈（こちらの推測）と必ず分けて**メモする。
- 上の記録シートで対象者×仮説の○×と実コスト値に落とし、成功基準を機械的に判定できる状態にする。
- **生データは `projects/self/sources/YYYY-MM-DD-problem-interviews.md` として1本のファイルに残し**、対象者ラベル・セグメント呼称・現行ツール名を本スクリプトの表記どおりに書く（学び LEARN の `sources` から辿れるようにする）。
- 想定と違った発言（驚き）は別枠でマークしておく（学習カードの「驚き・想定外」に直結）。
