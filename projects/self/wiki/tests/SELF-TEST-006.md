## テストカード（検証前に記入・後から書き換えない）

### 目的

[[SELF-DEC-002]]（FPF→CPF 巻き戻し）が最優先タスクとして事前登録した「**実データでの問題インタビュー**」を実施する。

核心クラスタ（[[SELF-H-004]] [[SELF-H-008]] [[SELF-H-006]] [[SELF-H-002]] [[SELF-H-001]]）は、いったん確信度7-8・検証済みに達したが、その根拠が**すべて実観測でない生成データ**だったため [[SELF-LEARN-005]] の揺さぶり監査で確信度6・検証中に是正されている（先行3ラウンド＝[[SELF-TEST-002]] [[SELF-TEST-003]] [[SELF-TEST-004]]）。本実験は同じ問いを**実在の実践者**に当て、〈実コスト〉〈行動〉の一次証拠で確信度7・検証済みを取り直し、CPF→FPF の再移行判断（`/deciding`）に足る土台を作る。

> **本文の語について**: 本カードは**実データ**の実験なので、先行ラウンドのデータ種別を指すときも判定マーカー語を本文に書かず、「実観測でない生成データ」と言い換えるかレコードID（[[SELF-TEST-002]] [[SELF-TEST-003]] [[SELF-TEST-004]]）で参照する。ビューと lint の判定（`tools/records.py` の `fictional_activities`。出典冒頭の宣言を一次情報とし、**本文マーカー語を後方互換のフォールバックにしている**）がマーカー語を拾い、実データの実験を誤って「実観測でない活動」に分類してしまうため。

> **この制約は本カードに紐づく学び（LEARN）と生データにも及ぶ**。判定は出典（`sources`）冒頭の宣言を一次情報とするので、本実験の生データ冒頭に宣言を書かず（実データなので書く理由がない）、LEARN 本文でもマーカー語を使わない。先行ラウンドとの対比はレコードID（[[SELF-TEST-002]] [[SELF-TEST-003]] [[SELF-TEST-004]]）で書く。破ると `check_fictional_cap` が実データ由来の確信度に上限8の蓋をかけ、ビューヘッダーが「実データ未検証」と表示する。

あわせて [[SELF-H-003]]（仮説の更新は報告サイクルに駆動される）を初めて検証対象に含める。この仮説は [[SELF-LEARN-002]] で「TEST-003 の対象外（核心クラスタに集中）のため据え置き」とされたまま確信度5で放置されており、**行動仮説3件のうち最も証拠が薄い**。

検証するのは CPF の中心の問い Q1〜Q7（[playbooks/cpf.md](../../../../playbooks/cpf.md)）であり、**ソリューションの検証は含めない**（[[SELF-H-009]] [[SELF-H-010]] の再検証は [[SELF-DEC-002]] の判断どおり保留）。

#### 対象外とする仮説とその理由

[[SELF-H-005]]（確証バイアス）・[[SELF-H-007]]（反証不能な曖昧仮説）は、重要度8・確信度4で「次に検証すべき仮説」に並ぶが、**本実験の対象に含めない**。

[[SELF-LEARN-002]] の観測では、この2件は**自認 5/5・3/5 に対して実コスト 0/5**だった。すなわちギャップは「課題を認識しているか」ではなく「コストを払うほどの痛みか」の側にある。本実験の成功基準は〈自認〉かつ〈実コスト〉の人数比で判定する形式なので、この2件を同じ枠に混ぜると**自認の高さが支持として数えられ、偽の支持を作る**。実コスト・行動のみを問う別のテストカードで扱う。

### 方法

**対象者**: `説明相手を持つ層`（上司・投資家・メンター・チームなど、検証の進捗を説明する相手を持つ実践者。呼称は [[SELF-LEARN-006]] の名寄せ規約の正規名）。**5名以上**。

**形式**: 1名 45〜60分の問題インタビュー。スクリプトは [SELF-TEST-006-script.md](SELF-TEST-006-script.md)。

**目的モード**: **ハイブリッド**（[playbooks/interviewing.md](../../../../playbooks/interviewing.md)）。

- **反証枠** — 対象6仮説それぞれに、支持側と対になる**反証質問**を置く。各仮説の反証条件（各仮説レコードの「反証条件」）を逐語で事前登録し（下記「成功基準」）、観測されたら確信度を下げる。
- **発見枠** — 既存仮説を相手に語らず伏せ、**自発言及だけ**を listen-for として記録する。特に (a) 記録運用が個人単位か共同編集か、(b) 既存8仮説のどれにも当てはまらない不満。[[SELF-LEARN-004]] の「単独Wikiが共同編集派に合わない」は既存の状況・行動仮説がどれも捕らえていない行動シグナルだが、**こちらから製品・ツール案を出さない**（CPF の鉄則）。

**CPF の鉄則**（[templates/problem-interview-script.md](../../../../templates/problem-interview-script.md)）: 過去の事実のみを聞く（未来の意向・仮定は聞かない）／**ソリューションは見せない・語らない**／誘導しない／一般論は「直近の具体例は？」で事実に降ろす。

**データ種別**: **実データ（実在の実践者）のみ**。実観測でない生成データを本実験に混在させない（混在させると [[SELF-LEARN-005]] が裁定したカテゴリーエラーが再発する）。禁止事項はスクリプト側にも明記した。

#### 記録の規律（事前登録・[[SELF-LEARN-006]] の再発防止）

[[SELF-LEARN-006]] は、機械 lint を通り抜ける3種の追跡可能性欠陥（対象者ラベルの表層形の乱れ／証拠1件の転記漏れ／不変カードと出典のコホート記述の矛盾）を検出した。テストカードは学び（LEARN）が紐づくと不変になるため、対策をここに事前登録する。

1. **現行ツールを冒頭で確定して記録する**。「どの既存ツールからの話なのか」を後から曖昧にしない（`Miro` `Notion` などは個別に書き、併記は `Miro/Notion` の形）。
2. **対象者ラベルは `対象者<英字>` で、`対象者U` から連番**（A〜T は既存3ラウンドで消費済み）。7人目以降は `対象者AA` `対象者AB` と続ける。**人数と命名数を一致させ、文字を飛ばさず、全員に一意な名前を振る**。ラウンド跨ぎの曖昧参照（`対象B系` 等）は使わない。
3. **セグメント呼称は正規名 `説明相手を持つ層` で固定**し、生データ・学び・本カードで**同一文言**にする。

### 指標

対象者ごとに以下を記録する（スクリプト末尾の記録シートがそのまま台帳になる）。

### 成功基準

**開始後は書き換えない**（後知恵バイアス防止）。人数の変動に耐えるよう**比率**で事前登録し、[CLAUDE.md](../../../../CLAUDE.md) の承認規律に沿って**機械的に〈支持〉／〈反証〉へ解ける形**に揃える。

- **人数の床**: 実施が **5名未満なら成功基準は一切発火しない**（判定は〈判断保留〉・確信度は動かさない）。CPF の移行基準「複数の顧客（目安5人以上）」に合わせ、3名中2名＝66% を通過と読ませない。
- **課題 [[SELF-H-004]] [[SELF-H-006]] [[SELF-H-008]]**: **60%以上**（5名なら3名）が〈自認〉**かつ**〈実コスト〉の**具体値**を挙げられる → 確信度 **7・検証済み**。
- **行動 [[SELF-H-001]] [[SELF-H-002]]**: **80%以上**で行動事実が観測される（H-001＝作る前の検証を反復した事実／H-002＝学びの記録先が3ツール以上に分散し探し直しに時間を払った事実） → 確信度 **7・検証済み**。
- **行動 [[SELF-H-003]]**: 「直近の検証で、**学びを得た日**と**仮説/確信度を更新した日**が同日でなかった」が **60%以上** → 確信度 **6**／**80%以上** → 確信度 **7**。
- **〈自認〉だけで上げない**。実コストの具体値が言えなければ × とする（interest ≠ intent）。
- **未来の意向・仮定は実コスト・行動に数えない**（「今後やろうと思っている」「無料なら試す」「あったら使う」）。[[SELF-LEARN-006]] が示したとおり、「無料枠で始める」は〈支払い〉ではない。
- **単一ラウンドの実データでは確信度8を取らない**。8 は2ラウンド目または行動追跡で取る。
- **発見枠から出た新規シグナルは既存仮説の確信度を動かさない**。学び（LEARN）の「驚き・想定外」に置き、`/formulating` の新規仮説候補として渡す。
- **反証側**: 下表の反証条件が観測され、かつ支持側の比率を下回った場合は確信度を **4** に下げ検証中を維持する。反証条件が **60%以上**で観測された場合は**ステータスを反証**に落とす。

#### 反証条件（各仮説レコードから逐語・開始後に変更しない）

| 仮説 | 反証条件（レコードから逐語） |
|---|---|
| [[SELF-H-001]] | 実践者の多くが「作る前の検証」をしていない、または検証を一度きりで終え反復していない。 |
| [[SELF-H-002]] | 学びが1箇所に構造化して集約されており、探索・再構成にコストが生じていない。 |
| [[SELF-H-003]] | 学習した直後に仮説・確信度を更新する実践者が多数を占める。 |
| [[SELF-H-004]] | 実践者が過去の意思決定の根拠を容易に再構成でき、記録の散逸に実コスト（時間・信頼）を払っていない。 |
| [[SELF-H-006]] | 実践者が interest と intent を仕組みとして区別できており、取り違えによる手戻り（無駄な実装等）が生じていない。 |
| [[SELF-H-008]] | 報告の場で証拠の共通の土台があり、証拠の解釈が割れず意思決定が滞りなく進む。 |

#### この実験の後

核心クラスタが実観測で確信度7以上・検証済みに達したら、[[SELF-DEC-002]] の「戻る先・次の一手」に従い CPF→FPF の stage-transition を `/deciding` で改めて判断する。達しなければ CPF に留まり、不足した証拠（実コストか行動か）を狙う次の実験を `/planning` で立てる。
