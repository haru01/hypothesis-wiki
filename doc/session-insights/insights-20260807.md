**Q1. Claude Code のセッションログ（`~/.claude/projects/` 配下）で使われている JSONL 形式の特徴として正しいものはどれですか？**

A) ファイル全体が1つの JSON 配列で、末尾に `]` が来るまでパースできない
B) 1行が1つの独立した JSON オブジェクトで、追記とストリーム処理に向いている
C) JSON にコメントとトレーリングカンマを許可した拡張形式である
D) バイナリ圧縮された JSON で、専用ツールでしか読めない

<details><summary>答え</summary>

**B) 1行が1つの独立した JSON オブジェクト**

JSONL（JSON Lines）は改行区切りで独立した JSON オブジェクトを並べる形式。ファイル全体を読み込まなくても行単位で逐次処理でき、追記専用ログ（セッションログ、イベントログ）と相性がよい。`grep` や `jq` でのフィルタも行単位で効く。

</details>

**Q2. meetup-sample-v2 で使われていた lefthook の説明として最も適切なものはどれですか？**

A) GitHub Actions のワークフローを記述する YAML の方言
B) Go 製の高速な Git フックマネージャで、commit/push 時のチェックを YAML で宣言的に管理する
C) TypeScript の型チェックを高速化するコンパイラプラグイン
D) 左手用キーボードショートカットを設定するツール

<details><summary>答え</summary>

**B) Go 製の Git フックマネージャ**

lefthook は `lefthook.yml` に pre-commit / pre-push などのフックを宣言し、並列実行やファイルフィルタをサポートする。husky と同種のツールだが単一バイナリで動き、依存が軽い。CI が落ちる前にローカルでガードする「シフトレフト」の要になる。

</details>

**Q3. git worktree を使う主な利点はどれですか？**

A) リポジトリの履歴を書き換えて容量を削減できる
B) 1つのリポジトリから複数の作業ツリーを同時にチェックアウトでき、stash や branch 切替なしに並行作業できる
C) リモートブランチを自動的にミラーリングして冗長化できる
D) サブモジュールを1つのディレクトリに統合できる

<details><summary>答え</summary>

**B) 複数の作業ツリーを同時にチェックアウトできる**

`git worktree add` は同じ `.git` オブジェクトストアを共有したまま別ディレクトリに別ブランチを展開する。ビルド成果物や未コミット変更を持つ本体を汚さずに、レビュー・実験・並行タスク（並列 AI エージェントの隔離を含む）ができる。同一ブランチを複数 worktree で同時チェックアウトはできない点に注意。

</details>

**Q4. Node.js 20 の EOL（End of Life）に関する判断で正しい考え方はどれですか？**

A) EOL 後もセキュリティパッチは無期限に提供されるので急ぐ必要はない
B) EOL とはメンテナンス（セキュリティ修正含む）の終了を意味し、EOL 前に LTS の次系列（22 など）へ移行計画を立てるべき
C) EOL は新機能追加の停止のみを意味し、運用には影響しない
D) 偶数バージョンは EOL の対象外である

<details><summary>答え</summary>

**B) EOL = メンテナンス終了。前もって次の LTS へ移行計画を立てる**

Node.js の偶数バージョンは LTS として Active → Maintenance を経て EOL に至り、以後はセキュリティ修正も出ない。依存アップグレード調査で「Node 20 EOL」が論点に挙がったのは、ランタイム自体の移行がライブラリ更新より影響範囲が広く、先に計画すべきだから。

</details>

**Q5. UTC で記録されたログを日本時間（JST）に変換するとき、正しいのはどれですか？**

A) UTC に 9 時間を足す（JST = UTC+9）
B) UTC から 9 時間を引く
C) 夏時間の期間だけ 8 時間を足す
D) UTC に 12 時間を足す

<details><summary>答え</summary>

**A) UTC に 9 時間を足す**

JST は UTC+9 の固定オフセットで、日本は夏時間（DST）を採用していないため年間を通じて +9 で変換できる。例: ログの `03:58 UTC` → `12:58 JST`。日付境界をまたぐ場合（UTC 15:00 以降は JST では翌日）に注意。

</details>
